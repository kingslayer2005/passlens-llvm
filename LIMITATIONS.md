# Limitations

While this research provides an interpretable framework for understanding ML-guided compiler optimization decisions using SHAP, it is subject to several structural and methodological limitations.

## 1. Code Size Objective vs. Execution Time
Our pipeline strictly evaluates "beneficial" passes as those that reduce the **static instruction count** (code size). We do not measure runtime performance (execution time) on real hardware. Reducing static instruction count often correlates with smaller binary sizes (like `-Oz`), but it is not a reliable proxy for execution speed (`-O3`), as loop unrolling or vectorization intentionally increase instruction count to improve latency or throughput.

## 2. Single-Pass Marginal Effects and Phase Ordering
Our labels are generated by evaluating the marginal effect of applying a single pass $P$ after a random prefix of passes. 
- This partly captures phase-ordering effects (how earlier passes condition the IR for later passes), but it does not fully model the combinatorial explosion of full sequence interactions.
- A pass might be detrimental locally but open up significant optimization opportunities for a subsequent pass. Our greedy, immediate-reward approach fails to capture delayed-reward optimizations.

## 3. Limited and Homogeneous Benchmark Suites
The models are trained exclusively on PolyBench/C and MiBench (with a potential capped fallback to AnghaBench). 
- PolyBench is heavily biased toward dense numerical loop nests and stencil computations.
- MiBench targets embedded systems.
- The learned heuristics and SHAP feature importance may overfit to the idioms of these specific suites and might not generalize to object-oriented code (C++), highly concurrent systems (Rust/Go), or different domains like web servers or compilers.

## 4. Static Feature Limitations
Our feature set relies entirely on ~60 static Autophase-style structural and opcode counting features (e.g., `add` instruction densities, CFG edge counts).
- We do not capture dynamic behaviors, such as memory access patterns, branch probabilities, or cache miss rates.
- Graph-level properties (like data dependencies and dominator trees) are only weakly approximated by predecessor/successor distributions.
- Advanced representation learning methods (like IR2Vec, ProGraML) could capture much richer semantic contexts than our flat, handcrafted feature vectors, though at the cost of direct interpretability.

## 5. Intraprocedural Scope
Our dataset extracts single functions into isolated modules (`llvm-extract`). As a result, we only evaluate **intraprocedural** passes. We entirely miss cross-module optimizations, Link Time Optimization (LTO), and interprocedural analysis (IPA/IPO) such as inlining, which are critical components of modern `-O2` and `-O3` pipelines.
